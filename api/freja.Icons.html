freja

Icons

Bundled SVG icons loaded from the classpath. The application stays offline-capable because the assets are shipped under src/main/resources/icons/mdi. During development, missing icons are fetched once from Iconify and cached in the source resource tree and in the compiled class path, so the next build bundles them and a packaged application never needs the network.

applicationImage()Image

Image

the 128x128 image of the currently selected design

The application image for the icon selected in the settings page. Windows need an Image rather than an Icon, so AppIcon paints each design into a bitmap.

applicationImages()ListImage

ListImage

images from 16 to 128 pixels, smallest first

The vector-rendered variants of the selected application icon. Supplying all of them lets the window manager pick a crisp 16 or 32px image instead of scaling the largest one down.

of(StringiconifyName, intsize, Colorcolor)Icon

StringiconifyName

the icon name, with or without an mdi: prefix
intsize

the display size in pixels
Colorcolor

the tint colour (may be a Theme dynamic colour)
Icon

the loaded icon

Loads any bundled Material Design Icons SVG by name. Accepts either "mdi:<name>" or just "<name>".

If the SVG is not bundled, the behaviour depends on the mode:

  • Packaged application: returns a neutral fallback icon. No network call is made, even when the working directory happens to be the project root.
  • Development: when running from an unpackaged class path that contains a src/main/resources tree, the icon is fetched once from Iconify, saved both into that tree (for the next build) and into the live class path (for this run), then used. The fetch runs on a background thread so the EDT is not frozen; a placeholder is shown until it completes. Invalid names or failed downloads also return the fallback.
Set -Dfreja.icons.download=false to force offline behaviour and -Dfreja.icons.endpoint=... to override the Iconify base URL.
