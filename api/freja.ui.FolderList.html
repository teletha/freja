The folder rail of the library, built on JList so only the rows inside the viewport are painted. A library which discovers ten thousand directories builds no components for the rows which are scrolled away: the model keeps plain Folder records and the renderer is one shared cell.

The visuals mirror laevatain.ARXNavList: a rounded selection wash, hover feedback, an icon, an ellipsised title and a right-aligned count.

FolderList()

updateUI()void

Reinstalls the look and the pointer handling after a look and feel change. JList installs its own mouse handler on every updateUI; leaving it in place would select a row twice and report the same click to the host twice.

setFolders(ListFolderfolders)void

ListFolderfolders

Replaces the folder rows. Rows which did not change are left alone. Selection follows folder identities: a removed folder cannot fall through to the row which took its place.

setOnSelect(ConsumerFolderhandler)void

ConsumerFolderhandler

Receives every folder the user selected with the pointer or the keyboard.

setOnRemove(ConsumerListFolderhandler)void

ConsumerListFolderhandler

ListFolder

setMenu(FunctionFolder, JPopupMenuprovider)void

FunctionFolder, JPopupMenuprovider

Installs the context menu. The provider builds the menu for the clicked folder; null disables the popup entirely.

setSelectedId(longid)void

longid

Marks a folder as selected without notifying the host. A negative id clears the selection. A multi-selection is kept when the requested folder is one of its rows: refreshing the view while several folders are selected must not silently reduce them to one.

reveal(longid)void

longid

Scrolls the list so the folder is visible; does nothing when it is not in the model.

scrolled()JScrollPane

JScrollPane

Wraps the list in a borderless scroll pane whose rows span the viewport width, so a long folder name cannot push the count out of sight.

boolean
