A virtualized, Picasa-like thumbnail grid.

Only the cells overlapping the clip rectangle are painted and only their thumbnails are requested. A library with tens of thousands of photos therefore scrolls with a small, constant cost.

scrollTargetFolder()long

long

the destination folder identifier, or -1

The folder whose section will sit at the top once the running scroll animation settles, or -1 when nothing is animating. A folder jump glides through the sections in between, and the sticky header reports each of them as it passes; persisting the current one while the window closes would reopen a folder the user was only travelling across.

visibleFolderId()long

long

the folder identifier, or -1

The folder whose section currently owns the top of the viewport, read from the layout rather than from the last painted sticky header. The header only catches up on the next paint, so a window closing in between could otherwise persist an older folder.

scrollToTop()void

Brings the view back to the first photo. Selecting the entry the grid is already showing is a deliberate request to return to its start, so it needs the same glide the folder jump gives.
